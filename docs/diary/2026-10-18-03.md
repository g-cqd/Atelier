# Diary — 2026-10-18 (03)

## Adopt TerminalKit 264f744

Goal: KittyCode gets the keyboard decoder fix (zero allocations per keystroke instead of one) by
pinning the TerminalKit revision `ask` already uses.

SwiftPM accepts one revision per package identity. TerminalKit `264f744` requires Aemi `5f0c47c`,
so AemiJSON moved first: `a6c2d58` on its main, 372 tests, exit 0. Then all three Atelier manifests
moved to TerminalKit `264f744`, Aemi `5f0c47c`, AemiJSON `a6c2d58`. Each lockfile changes exactly
those three revisions.

## SignalHandler changed under the runtime

Twelve TerminalKit commits separate `7a1f22a` and `264f744`. One is source-breaking here:
`SignalHandler.start()` now throws and returns nothing, `stop()` must be called, one handler owns
delivery per process, and callbacks arrive on a reader thread with the signal number.

The one-owner rule would make the parallel runtime tests fail with `.alreadyRunning`, and every test
session was replacing the test runner's SIGINT and SIGTERM dispositions. ADR-0003 injects the signal
session: production passes `SignalHandler`; tests pass `SignalSessionSpy`.

Two tests, written with the seam and proven by mutation:
- removing `defer { signals.stop() }` fails "a run stops the signal delivery it started";
- swallowing the start error fails "signal delivery that cannot start fails setup and still
  restores the terminal".

`TerminalConnection.readAvailable` is new but has a default implementation; nothing to adapt.
