# Fix plan for the 2026-09-23 codebase review

This plan orders the work that `2026-09-23-codebase-review.md` describes. Finding IDs, verdicts, severities and
corrected fixes come from that review, whose sections are cited as "review §n". Statuses are current to `5a990db`.
File paths follow the review's convention: `Atelier*` targets live in `Packages/AtelierCore/Sources/`, `Kitty*`
targets in `Apps/KittyCode/Sources/`, and `DiffComparison`, `DiffRendering`, `DiffTextKit` and `GitDiffViewer` in
`Apps/GitDiffViewer/Sources/`; test targets such as `GitDiffViewerTests` live in each package's `Tests/` directory.
Line numbers refer to `10ae905` unless they say otherwise.

## 1. How to read this plan

- **Waves run in order.** Within a wave, tracks are file-disjoint and can run in parallel. A track that needs another
  track's merge says so under "Depends on".
- **Every track gives** the findings it closes, the files it owns, the change (with the verifiers' corrections), the
  tests it adds, its acceptance criteria and a size.
- **Sizes are estimates, not measurements:** S is up to a day, M two to four days, L a week or more.
- **Work in flight.** While this plan was written, other sessions held uncommitted edits in `Apps/GitDiffViewer`:
  `DiffTextKit/StaticTextLayout.swift`, `StickyCardGeometry.swift`, `StickyCardView.swift`,
  `GitDiffViewer/Views/CombinedDiffView.swift`, `ContentView.swift`, `SettingsView.swift`, and new card-layout files
  and tests. Tracks 3H and 4F touch some of these files; start them from whatever lands.

**Rules for every track,** from `AGENTS.md` and the global standard:
- Swift Testing only, test names as backtick sentences, one behaviour per test.
- Event-driven waits only: `TestClock.waitForSleepers` then `advance`, `TaskProviderSpy.waitForAllTasks`,
  `AsyncProbe`, `CountProbe`. No `Task.sleep`, `Task.yield`, polling or wall-clock assertion.
- A regression test for each bug, failing before the fix.
- The GitDiffViewer app target cannot be tested: `GitDiffViewerTests` depends on `DiffComparison`, `DiffGit`,
  `DiffRendering` and `DiffTextKit`, not on the `GitDiffViewer` executable (`Apps/GitDiffViewer/Package.swift`). Logic
  that lives today in `GitDiffViewer/App.swift` or in a view moves first to `DiffComparison` (models and policies) or
  `DiffTextKit` (AppKit views), and gets its test there.
- Core targets start no unstructured task and use no `TaskProvider`; they expose `async` functions, task groups and
  streams the caller drives.
- Benchmarks are gated by `GDV_BENCH` and never run in the default `swift test`. Every performance claim carries a
  before and an after measurement.
- Moving code between packages: promote access in a separate no-op commit, then one `git mv` plus the manifest edits
  per commit, every package green after each.
- A shared test-support file (for example `ModelTestHarness.swift`) is edited by at most one track per wave; other
  tracks add new test files.
- Commit titles: `<Scope>: <sentence>`, the scope being the target or app most affected (`AtelierGit:`,
  `DiffComparison:`, `KittyCode:`, `Docs:`), under about 72 characters, with the detail in the body (book D19).

### 1A. Language-server trust gate, SDK probe directory and quit (GitDiffViewer, AtelierLSP)

- **Findings:** Sec C1, Sec L2, Sec M4, GDV S11, Core S9 (registry keys only), Aemi #5 (Atelier side), and step 4 of
  Sec H1's fix, quoted: "Disable Fetch for untrusted repositories."
- **Change:**
  - Record a trust decision per repository, keyed by its canonical root, untrusted by default, and ask the user
    explicitly (decision 7.5). Never pass an untrusted root to sourcekit-lsp as `rootUri` or working directory;
    untrusted repositories get the doc-comment and SDK tiers only. As an extra layer, send initialization options
    that turn off background indexing.
  - Key the LSP registry by the same canonical root, so `file:///repo` and `file:///repo/` share one server.
  - Resolve `lspServerLocations` through the project's key before starting a server. The SDK tier has no root and
    can only honour the app-wide value; decision 7.5 settles that asymmetry.
  - Memoize the SDK scratch service in a stored `Task`, set before any suspension.
  - Quit in the order verify-deps gives: cancel diagnostics first, then call the pools' blocking `shutdown()` off the
    main thread, and reply to `.terminateLater` when it returns or when a time limit expires. This plan adds
    cancelling in-flight git work before the shutdown, since git runs have no timeout except fetch; a cancelled
    `run` removes its queued job, so `shutdown()` does not start it.
  - Create the SDK probe directory with `mkdtemp` (mode 0700), put every probe URI under it, and fail instead of
    ignoring the error with `try?`.
  - Disable the Fetch menu items while the repository is untrusted.
- **Tests** (the policy types live in `DiffComparison`, so `GitDiffViewerTests` can reach them; `AtelierLSPTests`):
  - An untrusted root never reaches the language-server factory (a spy registry records no call), and hover still
    answers from the doc index.
  - Trusting a root through a symlinked path trusts its real path; revoking trust stops new sessions.
  - A project-level `lspServerLocations` disable stops the launch for that project only.
  - Two concurrent `sdkHoverProvider()` calls create one scratch service.
  - The shutdown sequence cancels diagnostics before draining, and finishes within its limit when a pool job never
    returns (`TestClock`).
  - The `initialize` request carries the background-indexing option (argument capture in the fake transport).
  - The probe directory has mode 0700, every probe URI lies under it, and a failed creation surfaces an error.
- **Acceptance criteria:**
  - Hovering in an untrusted repository whose `buildServer.json` names a marker command starts no sourcekit-lsp with
    that root, and the marker never appears.
  - A trusted repository hovers as before.
  - Quitting while a corpus lint runs returns control to AppKit within the time limit.
  - No `file:///tmp/` URI remains in AtelierLSP.
- **Size:** L.

    `git config --list -z --includes`, which executed nothing in the verifier's test, even with `core.fsmonitor` set.

- **Acceptance criteria:**
  - No payload from the verifier's experiment runs, on each git build it used: Homebrew git 2.55.0, Apple Git-155 and

### 1D. The core file watcher (AtelierFileTree)

- **Findings:** Core B7 (also reported as Aemi #4), Core B8, Aemi #26, the rest of Aemi #27, the rest of GDV S16, and
  the `FileWatcherTests` wait (Core S25).
- **Change:**
  - One FSEvents stream over every requested directory. A second `watchDirectory` restarts the stream over the
    union, from `FSEventStreamGetLatestEventId`, so no event is lost.
  - `watchFile` records the file's `realpath` and makes sure its parent directory is in the stream; the callback
    reports a watched path as `.fileChanged` and anything else as `.directoryChanged`. The per-file `DispatchSource`
    goes. The public API keeps its shape: `watchDirectory`, `watchFile`, `unwatchFile` and `suppressNotifications`
    stay, because both apps call them.
  - Suppression applies to both kinds of event, with `realpath`'d keys.
  - The event stream buffers at most 1,024 events (`.bufferingNewest`), and a caller can exclude up to eight paths
    (`FSEventStreamSetExclusionPaths`).
- **Tests:**
  - A write under the second of two watched directories raises an event.
  - A watched file keeps reporting after three atomic saves (write a temporary file, rename it over).
  - A suppressed path raises neither kind of event; an unsuppressed one does.
  - A file watched through `/tmp` reports under the path the caller registered.
  - Events written between two stream generations arrive once the new stream starts.
  - An excluded path raises nothing.
  - `FileWatcherTests` waits on events, not on `Task.sleep` (`:24` at `5a990db`).
- **Acceptance criteria:** every test above; both apps' suites pass unchanged; a linked worktree's refs raise events
  in GitDiffViewer with no change to `RepositoryFreshness`, whose second `watchDirectory` now works.
